# Skill: абзац → сегмент в оглядах судової практики

Сформовано на основі реальної роботи над `documents/markdown/Oglyad_KKS_2024/Oglyad_KKS_2024.md`.

## Формат результату
- Сегмент: `<!-- === SEGMENT: N.M | N. Назва розділу === -->`, порожній рядок, один абзац, порожній рядок.
- **Один абзац = один сегмент.** Якщо в сегменті кілька абзаців, кожен виноситься у новий сегмент (`N.M+1`, ...). Нумерація в межах розділу послідовна.
- **Абзац = один рядок:** текст позиції + посилання на постанову:
  `Текст... Постанова колегії суддів ... від ДД.ММ.РРРР у справі № ... (провадження № ...) <https://reyestr.court.gov.ua/Review/NNN>`
- Жорсткі переноси рядків (PDF-перенос) прибираємо, лишаємо один пробіл. Подвійні пробіли й помилки оригіналу (наприклад «кримінальнопроцесуальним») НЕ виправляємо.
- Заголовки і підзаголовки розділу додаються на початок абзацу через «. »:
  `Розділ. Підрозділ. Текст позиції...`. Нумерацію «1.» перед заголовком прибираємо.
## Стандартний 3-кроковий робочий процес (патерн розділів 4, 7, 8, 10)
1. **Злиття блоків:** Почергове злиття кожного виділеного тексту позиції з реквізитами судового рішення в один рядок.
2. **Префіксація:** Формування повного ієрархічного ланцюжка заголовків на початку кожного абзацу через крапку (`Розділ. Підрозділ. Текст...`), видалення зайвих окремих рядків із назвами та нумерації « 1.».
3. **Сегментація («один абзац - один сегмент»):** Розбиття підготовлених абзаців на індивідуальні сегменти з наскрізною нумерацією `N.1` ... `N.K` у межах розділу.

## Як працювати
1. Користувач виділяє діапазон рядків. **Номери рядків ненадійні**: редактор користувача має власний буфер, а файл на диску може відставати або змінюватись. Завжди шукай блок за початком тексту (`anchor`), а не за номером.
2. Файл містить некоректні UTF-8 байти: не редагуй його `replace_file_content`/`multi_replace_file_content` (вони падають на кодуванні). Використовуй Python з `errors='surrogateescape'`, `newline=''`, або скрипт нижче.
3. Для злиття використовуй [merge_paragraphs.py](scripts/merge_paragraphs.py):
   ```bash
   python3 .agents/skills/segment-paragraphs/scripts/merge_paragraphs.py FILE \
     --anchor "Початок першого рядка" [--prefix "Розділ. Підрозділ. "] [--new-segment "5.2 | 5. Назва"] [--dry-run]
   ```
   Блок закінчується на першому рядку з `reyestr.court.gov.ua`.
4. Після правки перевір через `grep -n "SEGMENT: N\." FILE` або `sed -n 'A,Bp' FILE`, що результат на диску правильний.
5. Скажи користувачеві перезавантажити файл у редакторі, бо старий буфер може перезаписати зміни.

## Вибір дії за запитом
| Запит користувача | Дія |
|---|---|
| «зроби один абзац» / виділення без пояснень | Злити рядки виділення в один (без чіпання заголовків поза виділенням) |
| «один абзац - один сегмент» | Злити + якщо кілька абзаців, додати мітки сегментів, перенумерувати |
| «у цьому тексті є декілька абзаців, а сегментів менше» | Розбити по сегментах |
| Виділення разом із заголовками | Заголовки йдуть префіксом через «. » |

## Підводні камені
- Редактор користувача двічі перезаписував мої правки старим буфером; перевіряй диск і нагадуй перезавантажити файл.
- Те саме посилання на постанову може траплятись у двох абзацах оригіналу, це нормально, не дедуплікуй.
- Скрипти, що розбивають по порожніх рядках, ламають речення з порожнім рядком усередині; перевіряй результат.
